# Implement a Build Contract

Confirm the current accepted Build Contract and implementation-attempt identity.
Enumerate every included Requirement, NFR, acceptance criterion, decision-authority
constraint, dependency, and verification expectation before changing code.

Implement the complete contract within LOCKED, BOUNDED, and DELEGATED authority.
Run applicable available checks, inspect the resulting changes, and re-evaluate every
contract obligation rather than only the edited path. Compilation, one green test,
or return of control is not completion.

Return a structured completion claim containing task, contract, and attempt identity;
per-obligation and LOCKED-decision assessments; known gaps; changed files; checks and
results; and external-verification requirements. The claim is a self-assessment, not
Evidence or workflow completion. On retry, focus first on the supplied defect while
preserving satisfactory work and rechecking the full contract.
